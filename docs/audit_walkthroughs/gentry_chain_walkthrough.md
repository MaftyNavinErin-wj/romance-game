## 系统总览（30 秒读完）

豪族 = 城里的本地大族 / 士族。他们手里有钱、有人、有舆论，但不直接归你管。你拿下一座城之后，要不要让豪族满意，是个长线博弈。

整个系统的**最底层状态**是 **B1 county.loyalty**——每个县独立的豪族支持度（0-100）。一座城有 3-5 个县，每县的 loyalty 各算各的。把每县按人口加权聚合起来，得到城级的 **C1 city.gentry**。

**A 区**所有东西，都是在影响 county.loyalty 的变化（每旬涨跌）。**C 区**是城级的派生函数（金产乘数、征兵费乘数等）。**D 区**是这些派生值的最终去向（影响金钱、士气、攻防、事件触发等）。

最关键的设计意图（v161 时确立）：豪族系统应该是**县级粒度**的——所有冲击都应该作用在县上，城级数值是聚合产物。但代码里有几条路径绕过了县级，直接改城级数值（D11、D12），这是 audit 时最该警惕的偏差。

## A 区 · 输入因子（每旬怎么涨怎么跌）

A 区所有节点都是为了回答一个问题：**这一旬，每个县的 loyalty 该 +X 还是 -X**？

### A1 县每旬 g1 漂移（核心算式）
每旬县级 loyalty 的"基础变化量"，用算式记成 `g1 = (g1Shared + prefectMod) × typeSens`。这一项是所有县共享的（同一城同一势力），后面再被县类型敏感度（A4）调制。`g1Shared` 是个累加器，A8/A9/A10 都往里加东西。

**白话**：先算"这旬总体环境对豪族友不友好"（g1Shared），再加"太守这个人对县的关系"（prefectMod），最后乘"这个县敏不敏感"（typeSens）。

### A2 太守 origin 修正
太守是本地人 / 外来士族 / 寒门出身 / 还是空缺，对每个县的修正不同。本地人最受欢迎（特别是太守老家本县直接 +0.5），其他都是负的。

**白话**：太守是哪儿的人，决定豪族对他买不买账。

### A3 武将驻守加成 g2
派多少武将驻守在该城，会让县 loyalty 涨。武将老家就在本县最有效（"地头蛇坐镇"）；武将的家族正好是本县豪族大族，再 ×2（被 A5 放大）；多个武将可以叠加，但有上限（不能堆 N 个武将就把 loyalty 拉满）。

**白话**：派武将守城会刷豪族好感，亲朋故旧来守效果最好。

### A4 县类型敏感 typeSens
每个县有个类型：seat（治所，第一大县）/ clan_base（豪族据点）/ common（普通县）。**只有治所有 0.5 惰性（变化打 5 折）**，其他两种都是 1.0 全速。

**白话**：治所反应慢半拍，其他县按 100% 变化。设计意图是让首县做"稳定锚"，避免一波操作把整城豪族打崩。

⚠ **v3 图说三档不同**，实际只有 seat 惰性，clan_base 和 common 完全一样。已修正 desc。

### A5 本族 ×2 系数（COUNTY_CLAN_SENS = 2.0）
当冲击或加成涉及到"这个县的本地豪族大家族"时，所有强度翻倍。三处生效：
- A3 武将驻守加成里，本族匹配项 ×2
- A6 家族忠诚冲击，作用到对应县时 ×2
- A11 朝议投票冲击，作用到 clan_base 县时 ×2

**白话**：豪族大家族享有"双倍话语权"。让大族的政治分量真正显出来。

⚠ 注意：**这个系数和 B4 magnate 标记是两码事**。本族 ×2 看的是"武将家族 vs 县家族"匹配；magnate ×1.5 看的是"这个县是不是 10 个大族之一"。两条独立的放大路径。

### A6 家族忠诚冲击 applyFamilyLoyaltyShock
某个家族的人出事时，全势力该家族的所有 clan_base 县**立刻**闹事（不等每旬结算）。三种触发：
- AI 挖角玩家武将成功（8092） → 玩家方该家族所有 clan_base 县 -15 ×2
- 玩家挖角 AI 武将成功（13948） → AI 方该家族所有 clan_base 县 -15 ×2
- 武将处决（23069） → 该家族所有 clan_base 县 -30 ×2

**白话**：哪个家族的人被处决或被对方挖走了，原势力的该家族所有豪族据点立刻翻脸。处决最狠。

> v4.1 修正：v4 误写"朝议斥退武将"，实际 13948 是玩家挖角对方武将成功的冲击。

### A7 迁民 / 易主冲击
两类大事件改 loyalty：
- **迁民**：从城 X 把人口迁到城 Y。两边的县都不爽（来源城更不爽），跨州迁更不爽，clan_base 县额外更不爽。
- **易主（被攻占或献城）**：城被打下来，新主子的 county.loyalty 按"治所/有族员/无族员"重置（详见 B5）。

**白话**：搬家和换主子都会把豪族打蒙，需要时间恢复。

### A8 stage 阶段调制（v172 加）
势力分三阶段（warlord 军阀 / regional 一方之主 / regime 政权）。两个数值按阶段调整：
- 占领期惩罚：军阀 -0.4 / 一方 -0.3 / 政权 -0.2（占了你的城就持续掉血）
- 自然漂移：军阀 0 / 一方 +0.05 / 政权 +0.10（自己的城会不会自然回血）

**白话**：势力越成熟，治理越得心应手。军阀阶段就是"打天下不养人心"，政权阶段才是"既扛得住又能聚人心"。

### A9 武将技能 onGentry
特定武将影响豪族变化速度：
- 荀彧·王佐：当官时，全势力豪族每旬 +0.3
- 吕蒙·攻心（SKILL_INLINE）：吕蒙围你的城时，该城每县 -3
- 孙权·坐断（SKILL_INLINE）：孙权当官 + 城在江东时，江东豪族 +0.15

**白话**：几个特定武将能改变豪族变化速率，有正有负。

### A10 科技 gentryRecovery
两个民生科技：
- civ5 地方自治 +0.15/旬
- civ6 士族联姻 +0.15/旬（可叠加到 +0.30）
- civ6 还附带占领期 -20%（间接帮 D13）

**白话**：研究科技会让豪族每旬回血变快。

### A11 朝议投票冲击
朝议时通过/否决某个派系的提案，对该派系**老家所有州的 clan_base 县**立刻冲击：
- 采纳 +5 ×2 = +10
- 驳回 -3 ×2 = -6

**白话**：朝议是另一条独立的豪族传导通道。一次决策能影响整个地域的豪族。和事件不一样，朝议改的是 county 而不是 city（设计正确）。

## B 区 · 县级状态（最底层数据）

### B1 county.loyalty ⭐ 核心
每县独立的 0-100 数值。所有 A 区的输入最终都打到这里。这是整个系统的"地基"——其他所有数值都从这里聚合或派生。

**白话**：每个县的"豪族满意度"，独立维护。就这一个数。

### B2 县 gentry 档位
把 county.loyalty 量化成 5 档：拥戴(≥80) / 支持(≥60) / 中立(≥40) / 不满(≥20) / 抗拒(<20)。每档预设了 4 个数值（金产乘数、征兵费乘数、士气加成、防御乘数），供 C 区派生函数查表。

**白话**：把数值分成 5 个标签档，方便后面查表。

### B3 popShare 权重
每个县占整城多少比例的人口。聚合时按这个加权：city.gentry = Σ(county.loyalty × popShare)。

**白话**：人口大县发言权大。

### B4 magnate 标记
**7 个**豪族总堂县（长社/温县/朐县/扶风/吴县/吴陵/谯县）的 county 上 magnate=true 标签。**只影响 C2/C3 派生函数**：金产 ×1.5、征兵费 ÷1.5。

**设计意图**：经济杠杆。让玩家觉得"打下颍川的长社 ≠ 打下颍川随便一个其他县"——总堂县是双向放大杠杆，loyalty 高时双倍受益、loyalty 低时双倍翻车。激励玩家围绕这些核心县做战略决策（争夺/守住/卡死对方大本营）。

**白话**：总堂县是大杠杆，得人心则双倍受益、失人心则双倍翻车。注意它跟 A5 的 ×2 系数是两码事——A5 看"武将家族 vs 县家族"匹配，B4 看"这个县是不是大族总堂"。

> v4.1 修正：v4 误写"10 个"，实际 grep 出来是 7 个。

### B5 county 初始化映射
开局或城被攻占时，每县的初始 loyalty 怎么定。规则简化版：
- 你是本土势力（这块地是你老家）：治所 90 / 有官的大族县 70 / 没官的大族县 55 / 普通 50
- 你是外来政权：治所 40 / 有族员有官 45 / 有族员无官 30 / 没族员 20 / 普通 30

外加 E3 gentryHook 的修正叠加。

**白话**：开局/换主时定基准。本土势力受欢迎，外来要看你这边有没有该家族的人当官。

## C 区 · 城级聚合（数值整理 + 派生）

### C1 city.gentry ⭐ 核心
城级豪族支持度。**理论上**应该只是 county.loyalty 的加权聚合产物（v161 设计）。但实际代码里它还被很多地方直接读和直接写——这是 v161 设计意图没完全实现的地方。

**白话**：城级豪族总分，应该只是聚合产物，但代码里仍被多处直接读写。这是设计偏差的核心位置。

### C2 金产乘数 getGentryGoldMult
按县独立查档（B2 → goldMult），magnate 县再 ×1.5，按人口加权。从拥戴到抗拒分别 ×1.10 / ×1.05 / 1.00 / ×0.85 / ×0.65。

**白话**：豪族越拥戴，城里产金越多。

### C3 征兵费乘数 getGentryRecruitMult
同上结构，但作用到征兵成本。豪族越支持，征兵越便宜。magnate 县进一步打折。

### C4 守军士气修正 getGentryMoraleMod
**只**影响开局攻城时守军的初始士气。和 D3 城民心是两码事（D3 是另一条独立路径）。

### C5 防御乘数 getGentryDefMult
被攻城时守方防御力的豪族倍数。拥戴县 ×1.25 协防，抗拒县 ×0.5 怠战（相当于半数兵力）。

### C6 stage 钳制 STAGE_GENTRY_BOUNDS（v172 加）
每旬 processGentry 末尾，按势力阶段对 city.gentry 和 county.loyalty 做硬钳制：
- warlord：25-70（强权保底，但不得拥戴）
- regional / regime：0-100（完全解锁）

**白话**：势力阶段决定豪族的"政治上限"。军阀靠刀把子摁住下限不至崩，但也聚不起人心；只有正式政权才有上 80 拥戴档的资格。

## D 区 · 输出端（豪族影响什么）

D 区每个节点都是"豪族数值最终影响了什么游戏机制"。

### D1 城金产
城每旬产金 = 基础 × 人口 × 税率 × ... × **C2 豪族乘数** × ...。豪族是其中一个因子。

### D2 城腐败率
腐败率公式里的豪族修正项：5 档（≥80 +15% / ≥60 +8% / 0 / ≥20 -8% / <20 -15%）。**直读 city.gentry**，绕过 C 区派生层。

⚠ **v3 图说成 2 档**（≥80 / <20），实际是 5 档独立映射（CORRUPT_GENTRY_MAP，不复用 GENTRY_LEVELS）。已修正。

### D3 城民心回复
民心每旬变化里的豪族贡献：5 档（+0.3 / +0.1 / 0 / -0.3 / -0.6）。同样**直读 city.gentry**。

⚠ **v3 图漏写 20-40 档的 -0.3**。已修正。

### D4 征兵金费
招募部队的金钱 = 基础 × **C3 豪族乘数** × 兵营折扣 × 强宣称义兵 buff × (1+科技减免)。豪族是其中一个乘数。

### D5 扩编 / 补员金费
和 D4 同公式，作用到扩编（增加编制）和补员（损失后回血）。

### D6 守军初始士气
开局时守军部队的初始士气加上 C4 的修正。

### D7 攻城防御乘数
攻城战守方防御力 × C5。

### D8 献城（投敌）⚠ 反馈环
触发条件：某县 loyalty<20 + 该县人口占比≥20% + 城正被围 + 不是势力最后一城。**条件满足必触发，不是概率事件**（代码里没有 random 判定）。

**popShare≥20% 的设计意图**：保证"有分量的县"才能献城。小县豪族即使想献也没控制城门和军队的能力。20% 这个数字接近 7 个 magnate 县的 popShare 范围（0.18-0.20），所以基本等同于"只有大族总堂县才能献城"。

**对玩家的意义**：献城后调用 _triggerGentryBetray → applyGentryOnCapture（A7 的路径）—— 整个城的 county.loyalty 被新主子重置。
- **玩家方丢城**：城没了，A7 重置发生在敌方那边，玩家感受不到反馈
- **玩家方得城**（敌方城向玩家献降）：玩家方走 A7 重置 county.loyalty，确实有反馈

所以图上 D8→A7 这条边对玩家来说**只在"得城而非失城"方向上有意义**。

### D9 隐匿户口
某县 loyalty<20 + 该县人口超过初始 30% → 每旬流失 5% 城人口。豪族不爽时偷藏人口，长期会显著掉人。

### D10 C 类事件触发
4 个 C 类豪族事件的触发判据，都基于 city.gentry 或派系结构：
- C1 gentry_offer（豪族献策）：city.gentry > 70
- C2 gentry_pressure（士族逼宫）：派系影响力过大
- C3 humble_complaint（寒门抱怨）：寒门武将比例
- C4 gentry_unrest（豪族不满）：city.gentry < 30

事件触发后通过 D12 反过来改 gentry。

### D11 军令 SIEGE_AFTERMATH ⚠ 实现层 bug（high）
攻城胜利后下令屠城/劫掠/安民，**直接 ±gentryMod 改写 city.gentry**：
- pacify 安民 +5
- loot 劫掠 -15
- massacre 屠城 -40

**设计层 OK**：玩家就是在城的层面三选一做决策，决策语义本来就在城级——这没问题。

**实现层有 bug**：代码只写 `city.gentry += gentryMod`，**不写 county.loyalty**。下旬 processGentry 跑 _aggregateGentry，会按 county.loyalty 加权重新算 city.gentry——你的屠城-40 当场被覆盖，豪族第二旬就当无事发生。

**修复**：把 gentryMod 按 popShare 平摊到每个 county.loyalty，再用 _aggregateGentry 重算 city.gentry。这样既保留城级决策语义，又能让效果在县级落地，不会被覆盖。

### D12 事件直写 city.gentry ⚠ 分两组（high）
**11 个事件**的 effect 里直接 ±city.gentry。**要分两组看**：

**组 1：本来就是全城叙事（性质同 D11）**
- drought 旱灾、flood 水患（灾害本就影响全城）
- refugee_influx 流民、harvest_bounty 丰年（年景类）
- reckless_trouble 武将闯祸（武将影响全城）

这一组**设计层 OK**（事件叙事在城级），**只要修实现层 bug**——同 D11 修法，平摊到县。

**组 2：本来就有派系/县信息却懒得用（真·设计漏洞）**
- gentry_offer 豪族献策、gentry_pressure 士族逼宫（按派系触发，应作用到该派系的县）
- humble_complaint 寒门抱怨（与寒门武将相关，应作用到该武将派系的县）
- gentry_unrest 豪族不满（应只作用到具体闹事的县，loyalty 最低那个）
- C4 暴动 city.gentry = 0（一刀切归零，应只对暴动的县归零）

这一组的 condition 里**已经有了"哪个派系/哪个县/哪个家族"的信息**，但 effect 偷懒写成全城——这才是 v161 真正的设计漏洞。

**修复**：组 1 同 D11；组 2 留待专门的"事件链 audit"，每个事件按 condition 信息重新设计 effect 作用对象。

### D13 city.occupied 占领期
攻城胜利后写入 city.occupied = 倒计时旬数，按宣称强度分档：
- strong（强宣称） 3 旬
- medium 12 旬
- weak 18 旬
- none（无宣称） 27 旬

每旬 -1。**科技 occupiedMult 可缩短初始值（civ6 -20%）**。

**与 A8 的关系**：D13 是 A8 的"激活开关"。代码里写在 g1Shared 计算开头：

```js
if(city.occupied > 0) g1Shared += _occMod;
```

也就是说：**必须 city.occupied > 0 才生效**，否则 A8 的 _occMod（warlord -0.4 / regional -0.3 / regime -0.2）完全休眠。

- D13 决定：还有几旬要扛
- A8 决定：每旬掉多少（按势力 stage）
- 二者必须同时存在，惩罚才生效

**白话**：占领期长度由外交宣称强度决定（强宣称只需 3 旬，无宣称要 27 旬）；占领期内每旬掉血由势力阶段决定。两者一个是"持续时间"一个是"伤害强度"，缺一不可。

```js
function applyCityGentryDelta(city, delta){
  if(!city.counties) return;
  city.counties.forEach(co => {
    co.loyalty = Math.max(0, Math.min(100, co.loyalty + delta));
  });
  city.gentry = _aggregateGentry(city);
}
```
然后把 6 处 `city.gentry += delta` 都换成 `applyCityGentryDelta(city, delta)`。改一个函数解决所有覆盖问题。
